- `MUTATION_RESULTS.json`: `tools/mining-r2-scorer-mutation-check.js`, each mutant must turn at least one test red (the registry test file is in the set too). Four groups: the resolver, window-parameterised scoring, deferred seal and pending seal (M01 to M41); the first arrival program, chain verification, R1-median anchor and UNSEEN mark (A01 to A33, minus A22 to A24 whose code was removed); the R1 catch-up, industry window, readiness record, `requireChain`, `checkComplete`, CLI and `run.sh` wiring (B01 to B37 (minus B13, B14, B18, B36, B37)); the export script: read-only session, readiness, atomic day directory, industry window, fail closed, time limit, V6-window slots, point-in-time cutoff (D01 to D37; the SHA256SUMS test is skipped under `QRP_MUTATION_RUN` because every mutant edits the script on purpose).
- `REAL_CALENDAR_CHECK.json`: the resolver run on the real lane-copy calendar (read-only, throwaway ledger): the format parses, the calendar ends 2026-12-31, so R2 is NOT_READY ("listed 0 open days after 2026-12-31, need 54"). There is no real R2 data and no 2027 calendar yet.
- The end-to-end scoring test builds R2's directory the way production does: the fixture's holdout days inside a window that differs from R1's at both ends are dropped per day (seven tables and the readiness record), the arrival program writes the sealed directory (pending seal, base files, per-day parts, SHA256SUMS lines, hash chain), the rows before the window go to a separate "prior" directory standing in for the R1 directory, and the scorer verifies the chain.
- Not covered by a test, by design: the resolver counting from a real 2027 calendar (it does not exist); the export script against a database (it is tested with a stub docker and a stub psql; the SQL in `sql/*.sql` is the spec's and the only copy; the lane has no database driver); the CLI line that maps `--require-arrival-chain true` to the scorer's `requireChain` (the flag is in `run.sh`, tested, and the library option is tested, but no scoring run goes through the CLI with the flag); the real V6-side install (ops-coord, after plan-coord review).
