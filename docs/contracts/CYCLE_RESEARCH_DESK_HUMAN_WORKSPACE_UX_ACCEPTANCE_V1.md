## UX1. Desk 上下文优先

1. 全站第一识别顺序必须是“市场 → 策略 → 当前用途/状态”，不得以 case、family、bundle、experiment、race、release、hash 或 runtime ID 作为首屏主标题。
2. 当前真实首案显示为“美股 / US_V5 ETF 主策略 / 3,000 美元模拟账本”，同时明确其运行模式、数据截至、研究就绪状态和生产影响。
3. A 股与加密若没有已入账的运行／研究 case，必须显示“尚未接入真实研究 case”；不得把平台工程样例冒充为 Desk 当前策略，也不得把缺失显示为 0。
4. 策略、市场和状态中文名由一个后端只读展示投影产生；Web 不独立重算业务判断。

## UX2. 全站按用户问题组织

保留已有 hash 路由兼容性，但导航与每页任务改为：

1. `#strategies`：系统总览——“Research 当前覆盖了哪个 Desk 市场和策略？”
2. `#runtime-research-loop`：当前策略体检——“这个策略现在能不能进入完整体检，卡在哪里？”
3. `#experiments`：研究问题——“Desk 提出的哪个问题正在研究，证据是否冻结？”
4. `#races`：方案对比——“原版与候选方案谁更合适，结论是否锁定？”
5. `#shadow`：前向观察——“锁定结论是否进入前向观察，样本是否足够？”
6. `#promotion`：采用与复盘——“结论是否回到 Desk，是否采用，对生产有什么影响？”
7. `#runtime-status`：数据与运行状态——“实际输入是否新鲜、完整、可回放，Research 有哪些权限？”

每页首屏必须直接回答该问题，并显示下一步；不能要求用户先解释内部 schema 或 ID。

## UX3. 渐进披露与真相边界

1. 内部 ID、hash、文件绝对路径、schema、adapter、release 和 runtime 引用只允许出现在默认折叠的“技术详情”中。
2. 工程演示／历史样例必须与当前 Desk 首案分区，并默认折叠，标明“不是 Desk 当前策略，不影响当前首案与生产”。
3. `UNKNOWN`、`MISSING`、`NOT_VERIFIED`、`OUT_OF_SCOPE`、`NOT_APPLICABLE` 与数值 0 必须分别表达。
4. 当前首案没有研究问题、对比结果、前向观察或采用记录时，页面显示诚实空态、缺少什么和下一步；不得展示无关样例填满页面。
5. 所有页面保持只读；不得新增审批、发布、激活、交易或生产写入口。

## UX4. 可用性与状态覆盖

1. 桌面与 360 CSS px 宽度均不得产生整页水平滚动；信息层级在移动端仍按“结论 → 证据 → 技术详情”。
2. 导航和 disclosure 可键盘访问，有清晰焦点；正文与状态标签满足可读对比度。
3. 加载、读取失败、无真实 case、部分缺失和正常态都有明确中文反馈；错误态提供可执行的重试。
4. 页面标题、导航、主结论不显示裸内部 ID。搜索内部 ID 只能命中技术详情或机器可读属性。

## UX5. 确定性验收证据

1. 后端工作台投影测试证明：真实首案的人类标签、三个市场覆盖状态、七个用户任务视图、缺失与 0 分离、安全不变量和技术引用都来自同一 canonical read model。
2. API 测试证明 `/api/workspace` 只读可访问，普通 POST 仍为 405；既有原始只读端点保持兼容。
3. 静态测试证明七个中文导航、每页问题、诚实空态、技术详情、重试和只读边界存在，且不包含产品写入口。
4. 浏览器走查依次验证七页的真实首案上下文；至少验证桌面与 360 CSS px 响应式布局、键盘焦点、加载/错误呈现。
5. QRP 全量测试、Research Web JavaScript 语法、schema 验证和 `git diff --check` 为 0 fail。
