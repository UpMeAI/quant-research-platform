# Cycle × Research × Desk：研究队列与复盘采用页面关系冻结修订 2

状态：FROZEN  
冻结日期：2026-10-24  
Owner 决定：保持当前页面设计，冻结 `#experiments` 与 `#promotion` 的上下游关系。  
前序合同：

- `docs/contracts/CYCLE_RESEARCH_DESK_HUMAN_WORKSPACE_UX_ACCEPTANCE_V1.md`
- `docs/contracts/CYCLE_RESEARCH_DESK_HUMAN_WORKSPACE_UX_ACCEPTANCE_AMENDMENT_1.md`

本修订只冻结 Research Web 的产品语义、信息架构和状态流转边界，不改变策略参数、研究槽顺序、运行状态、采用结果或生产权限。前序合同中未被本修订明确替代的条款继续有效。

## B1. 两页的固定职责

### `#experiments`：研究队列

1. 固定回答：“哪些 Desk 问题正在研究，原版与候选方案是否已有锁定结论？”
2. 固定包含两个主区：“真实研究问题”和“锁定方案对比”。
3. 展示从 Desk 复盘进入 Research 的全部真实问题，包括尚未冻结、研究中、证据不足和已有锁定结果。
4. 负责表达研究内容、冻结状态、方案比较和系统结论；不承载用户采用决定，不提供审批、发布或激活入口。

### `#promotion`：复盘与采用

1. 固定回答：“结论是否回到 Desk，用户如何决定，对生产有什么影响？”
2. 只展示已经形成锁定结果、可以回到 Desk 处理的真实研究项，以及其待决定、采用、不采用或继续观察状态。
3. 负责表达 Desk 往返、用户决定与生产影响；不得在本页重新计算实验胜负或生成研究结论。
4. 固定保留“用户决定与系统结论分开”的提示和 Research 不能下单、不能代替用户采用、不能写生产参数的安全边界。

## B2. 固定上下游关系

产品链路固定为：

`Desk 研究问题 → #experiments 冻结与评价 → 锁定研究结果 → #promotion Desk 复盘 → 用户决定 → 生产影响`

1. 两页必须消费同一 canonical 运行／研究 link；前端不得用名称或相似字段自行拼接。
2. 未锁定的研究问题只能留在 `#experiments`，不得提前出现在 `#promotion` 的可处理列表。
3. 锁定研究结果进入 `#promotion` 不代表已采用；用户最终决定必须保持独立字段和独立权威来源。
4. “不采用”与“继续观察”均为合法用户结果；系统不得把它们改写为研究失败。
5. 没有研究问题时 `#experiments` 独立显示研究空态；没有锁定结果时 `#promotion` 独立显示复盘采用空态。一个页面为空不得用另一个页面的工程样例填充。

## B3. 冻结的导航与页面边界

1. 顶层名称固定为“研究队列”和“复盘与采用”，路由分别固定为 `#experiments`、`#promotion`。
2. 两页保持上下游分离，不合并为一个页面，不交换职责，不把采用控件放进研究队列，也不把实验配置放进复盘采用页。
3. 原 `#races` 继续作为 `#experiments` 内“锁定方案对比”的兼容入口，不新增第二套对比页。
4. 裸内部 ID、hash 和工程样例继续遵守修订 1 的渐进披露与单点技术披露规则。
5. 后续如需改变页面名称、职责、进入条件、上下游方向或合并关系，必须新增版本化修订；不得直接改写本冻结文本。

## B4. 确定性验收

1. 投影测试必须构造“未锁定问题”和“已锁定结果”并证明：两者都进入研究队列，只有已锁定结果进入复盘与采用。
2. 静态测试必须证明两条固定路由、两组页面问题、“真实研究问题”“锁定方案对比”“用户决定与系统结论分开”和三项安全边界仍存在。
3. Research API 保持只读；页面不得新增 review、approve、publish、activate、order 或生产参数写入口。
4. 当前首案没有真实研究 link 时，两页继续显示各自诚实空态；不得因本修订产生研究、采用或生产事实。

## 冻结后的当前真相

- 当前 US_V5 首案尚无真实研究问题或锁定结果，所以两个页面当前均为空。
- 当前 M1 仍被原生扫描包、适用基准行情和完整监管费用阻断。
- M0–M3 状态不变，`Production effect = NONE`，Research 隔离不变。
