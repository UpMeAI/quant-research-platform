# Cycle × Research × Desk：人类可读研究工作台验收 V1 修订 1

状态：FROZEN  
冻结日期：2026-10-24  
修订原因：目标用户确认原七个并列页面重复展示首案上下文，且“策略总览”实际只列 Research case，无法回答 Desk 有哪些运行、观察和历史策略；“当前策略体检”与未来策略详情职责重叠。  
被修订合同：`docs/contracts/CYCLE_RESEARCH_DESK_HUMAN_WORKSPACE_UX_ACCEPTANCE_V1.md`  
上游产品验收：`docs/contracts/CYCLE_RESEARCH_DESK_V8_1_PRODUCT_MILESTONE_ACCEPTANCE_V1.md`

本修订只改变 Research Web 的信息架构与只读展示投影，不改变任何 Desk 策略、运行状态、研究状态、阶段结论、采用状态或生产状态。V1 中未被本修订明确替代的条款继续有效。

## A1. 策略总览的权威范围

1. `#strategies` 展示 Desk 已登记的系统策略目录，而不是 QRP case、实验、bundle 或其他内部对象清单。
2. 策略范围、市场、运行角色、生命周期和人类名称必须只读消费 Desk 的权威生产者；前端不得维护第二份策略目录或独立判断生命周期。
3. `USER_MONITOR_ONLY` 个人持仓账本不作为系统策略卡片。每个 Desk 策略只出现一次。
4. 默认区展示运行中、模拟运行及研究观察策略；已关闭和停止接收新开仓的策略进入单独的“历史与收尾”区。
5. Desk 目录暂时不可读取时必须显示明确失败态，不得退回 QRP 工程样例或硬编码伪造完整目录。

## A2. 策略卡与详情

1. 每张策略卡以“市场、可读策略名、运行模式、生命周期、Research 关联状态”回答用户问题，裸内部 ID 不出现在主界面。
2. 每张卡都是可键盘访问的链接，进入 `#strategy-detail?strategy=<strategy_ref>`。
3. 策略详情是单一归属页，顺序包含：运行概览、体检与证据完整性、研究问题与方案对比、前向观察、复盘与采用。
4. 没有 QRP case 的 Desk 策略仍可进入详情，但必须诚实显示“尚未接入 Research”，不得套用当前 US_V5 首案证据。
5. 详情内的运行事实、Research 关联、结论和用户决定必须保持不同来源与未知状态；系统结论不得覆盖用户最终决定。

## A3. 导航去重与兼容

1. 顶层主导航收敛为：策略总览、研究队列、前向观察、复盘与采用、数据与运行状态。
2. 原 `#runtime-research-loop` 保留为兼容入口，进入当前首案详情的“体检与证据完整性”位置，不再作为顶层并列页面。
3. 原 `#races` 保留为兼容入口，进入合并后的“研究队列”；对比仍在策略详情与研究队列内呈现。
4. 工程里程碑 M0–M5 与历史技术样例只在“数据与运行状态”的折叠技术区展示，不得混入策略体检主内容或在所有页面重复。
5. 全站安全说明保留一个持续可见入口；具体只读边界在相关页面按需解释，不重复占据每个策略卡。

## A4. 当前首案与产品真相

1. 当前真实首案仍是 `RRC-US-V5-3000-V8-1-M0`，策略为 `US_V5_ETF_3000USD`，旧实验冻结基线为 `US_V5_ETF_6000USD`。
2. 当前 M1 仍为阻断：缺原生扫描包、适用基准 bars 和完整监管费用；信息架构调整不得把它提升为 READY。
3. M0–M3 产品阶段状态、缺少目标交付环境证据、`Production effect = NONE` 与 Research 隔离保持原样。
4. 策略目录的“运行中”只表示 Desk 生命周期，不等于已接入 Research、已完成体检、研究有效、已采用或可交易。

## A5. 确定性验收

1. 后端测试证明策略目录从 Desk 权威模块读取，并覆盖运行、观察、收尾、关闭、未接入 Research、当前 case 和冻结基线。
2. `/api/workspace?strategy_ref=...` 返回同一 canonical read model 的目录与所选策略详情；未知策略 fail closed，POST 仍为 405。
3. 静态测试证明五个顶层导航、可点击策略卡、五段详情、兼容路由、空态、错误态和技术内容单点披露存在。
4. 浏览器走查验证桌面与 360 CSS px：总览可辨认策略范围、卡片可进入详情、详情内五段可达、旧体检链接可兼容进入、无整页水平滚动、键盘焦点清晰。
5. QRP 全量测试、Research Web JavaScript 语法、schema 验证和 `git diff --check` 为 0 fail。

## 修订后的完成边界

- 本修订可证明用户能看懂 Desk 策略范围并进入一致的策略详情。
- 本修订不证明 M1 已完成，不新建研究问题，不运行实验，不改变参数，不采用方案，不触碰生产与资金。
- “页面可用”与“阶段产品交付”继续分开记录；没有目标用户在获准目标环境完成整条任务的证据时，M0–M3 不得因本修订转为已交付。
