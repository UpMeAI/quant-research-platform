# RF1116 `run.sh score` / `rescore` facts for the unattended timer (brief #151)

Written by LLM_GEN 2026-11-23 13:5x CST (clock read), from QRP `claude/rf1116-r2-scorer` (stacked on #153, not merged) and the lane on 2026-11-23. Facts, not design. "R2" lines exist only once the scorer PR (due Wed 11-25 12:00) merges; everything else is on `origin/main` today.

## 1. Command lines

```
run.sh score   <round_id> [<exclusions.json> <its sha256>]
run.sh rescore <round_id> "<reason>" <crash.log> [<exclusions.json> <its sha256>]   # same exclusions args as the score, else INPUTS_CHANGED
RF1116_HOLDOUT_SEGMENT=R2 run.sh score <round_id>    # R2 only (scorer PR): mounts the R1 directory read-only as --prior-live
```
`run.sh` itself needs `RF1116_RUNNER_IMAGE=qrp-round-runner:<commit12>` and runs `docker run --network none --user 1000:1000 --cpus 6 --memory 24g`. Container uid 1000 = host uid 100999 (userns remap).

## 2. Preconditions for `score <round_id>` (all checked before the vault open; a refusal does NOT spend the open)

1. **Clock:** now (+08:00) >= 2027-01-01T00:00+08:00 (`MINE_RUNNER_HOLDOUT_BEFORE_SEAL_END`). R2 (scorer PR): >= max(2027-01-01, window end + 1 day), the window end comes from the resolution record.
2. **Round:** head status `OPEN` or `CAP_REACHED` (selection written). Terminal statuses (`CLOSED`, `FAILED_RESCORE`, `FAILED_PARTIAL`, `FAILED_EVALUATION`) are refused (`MINE_RUNNER_ROUND_FAILED_*`). `SCORING` = already opened: `score` refused `MINE_HOLDOUT_ALREADY_OPENED`; only `rescore`.
3. **Selection:** `MINING_SELECTION_V1` row exists and `out/rounds/<id>/selection.json` sha256 == the row's `selection_sha256` (`MINE_RUNNER_SELECTION_FILE_MISMATCH`). A selection with `selected: []` writes `score.json {opened:false}` and exits 0 without opening.
4. **Mechanism review (R1.5, R1.10):** latest `MECHANISM_REVIEW_V1` exists, covers every survivor, its `mechanism_set_sha256` equals the current registrations, hash intact, dated before the open: else `MINE_RUNNER_MECHANISM_REVIEW_MISSING | _INCOMPLETE | _STALE | _HASH_MISMATCH | _AFTER_OPEN`.
5. **Seal:** a `HOLDOUT_SEAL_V1` row for the round whose `data_sha256` is either sha256(SHA256SUMS) or sha256(SHA256SUMS.sealed) of the holdout directory.
6. **Holdout directory** (`/srv/research-lane/rf1116-mining/holdout-sealed/<dir>`; R1 today: `rf1116-cn-a-daily-holdout-from-20261019`, `drwx------` kayla, files 0444, D1 = 2026-11-17, 7 sealed lines):
   - hand-over step: `chmod -R a+rX <dir>` first (the container uid is not kayla); the timer has to do this or the open fails with a read error;
   - `SHA256SUMS.sealed` untouched; every sealed line still in `SHA256SUMS`; every csv listed; every listed file present with the listed sha (`..._FILE_UNLISTED | _FILE_MISSING | _FILE_SHA_MISMATCH`); the 7 tables present (`..._TABLE_MISSING`);
   - calendar READY SSE rows reach the segment end (R1 2026-12-31), every SSE open day 2026-10-19..12-31 has >= 4000 distinct non-BJ names in prices, daily_basic, adjustment factor and >= 0.5 x the sealed-day median (`..._HOLDOUT_INCOMPLETE:<file>:<day>:<n>`, `..._HOLDOUT_SEALED_DAYS_EMPTY`);
   - field-state floor 0.9 x sealed median per daily_basic field per day (see section 6);
   - no holdout day in the lane copy or validation tail (`..._HOLDOUT_DAY_IN_NON_HOLDOUT_SOURCE`).
   - **R2 only:** `SEAL_PENDING_V1.json` sealed; the arrival chain `ARRIVAL_CHAIN_V1.jsonl` must verify (`..._HOLDOUT_ARRIVAL_INVALID:<reason>` = tampering, no retry; `..._HOLDOUT_INCOMPLETE:arrival:<day>` = a day has not arrived yet, retry later); the end-resolution record must exist (`..._SEGMENT_END_UNKNOWN`); R1 must be scored first (R1 directory is the `--prior-live` history).
7. **Counts:** the vault opens once per round; a segment can be opened by at most 2 rounds counting by amendment 1.2 (`MINE_ROUND_HOLDOUT_EXHAUSTED` is checked at round open, not at score).
8. **Windows:** `rf1116-score` and `rf1116-rescore` are `docker pause`d by the window-pause timer Mon-Fri 06:30-08:00, 09:15-15:30, 18:10-20:45 CST (a pause only delays the run, it is not a crash). Run time of a real `score` is not measured yet (no real score has been run).

## 3. Exit codes and output

| exit | meaning | stdout / stderr |
|---|---|---|
| 0 | scored and closed | stdout one JSON line `{"command":"score","round_id":...,"opened":true,"records":N,"passes":P,"status":"CLOSED"}` (rescore: `{"command":"rescore","rescored":true,...}`) |
| 2 | any refusal or crash inside the CLI (before or after the open) | stderr one JSON line `{"error":"MINE_RUNNER_<CODE>"|"MINE_<CODE>","message":"<code>:<detail>"}` |
| 3, 75 | generate/resume only (STOPPED / WAITING); never from score | - |
| 125/126/127 | docker could not start (image, mount, missing `--holdout` dir) | docker's stderr |
| 137 / 143 | the container was killed (OOM or `docker stop`) after the start: **may be past the open** | none from the CLI |

A non-zero exit does NOT say whether the vault was opened. Decide from the ledger (section 5).

## 4. Once-per-round guard and what each state means

- `holdout-vault.open` throws `MINE_HOLDOUT_ALREADY_OPENED` if a `HOLDOUT_OPEN_V1` row exists for the round. The open row is written right after the checks and BEFORE any G-MINE record; the round head goes to `SCORING` with it.
- `rescore` is accepted only when all hold: head is `SCORING`; an open row exists; fewer gate records than candidates; no `HOLDOUT_RESCORE_V1` event yet; selection row byte-unchanged; every input equal to the open (`inputs_sha256`: holdout manifest and SHA256SUMS.sealed, selection.json, factor series, data sources, code, floor, registrations, review, exclusions file); latest review predates the open; **the first attempt wrote no `MINING_GATE_RECORD_V1`**. Otherwise `MINE_HOLDOUT_RESCORE_SELECTION_CHANGED | _INPUTS_CHANGED | _RECORDS_EXIST`.
- Crash after >= 1 gate record: `rescore` closes the round `FAILED_PARTIAL` (R1.12; records VOID, 0 passes, attempts stay in N, open still counts) and exits 2 with `MINE_RUNNER_RESCORE_RECORDS_EXIST`. A rescore that itself crashes: the next `rescore` closes `FAILED_RESCORE` (exit 2 `MINE_RUNNER_RESCORE_FAILED`). After either, every further score/rescore is refused (`..._ROUND_FAILED_PARTIAL | _FAILED_RESCORE`). R1.8/R1.12 therefore need `rescore` exactly once after a crash past the open; it needs `<reason>` text and a crash log file (the timer can write `docker logs`/stderr to a file).
- `rescore` also mounts the same exclusions file, else the inputs differ.

## 5. Where outputs land (`/srv/research-lane/rf1116-mining/out/qrp-data/research/` unless noted; host user kayla can READ all of it: files 0644, dirs 0755, owner 100999; it cannot write)

- `holdout_vault.jsonl`: `HOLDOUT_OPEN_V1` (with `pre_open_checks.holdout_dir`: floors, per-day counts, `field_states_per_day`, exclusions; R2: `pre_open_checks.segment_window` with the resolution record hash) and `HOLDOUT_RESCORE_V1`.
- `mining_gate_records.jsonl`: one `MINING_GATE_RECORD_V1` per candidate (the G-MINE verdict, the item-9 mechanism check inside).
- `mining_rounds.jsonl`: the round head rows; after `close` a row `status: CLOSED` with `gmine_passes`, `gmine_basis`, `closed_at`.
- `out/rounds/<round_id>/score.json` (`MINING_RUNNER_SCORE_V1`), `out/rounds/<round_id>/access_log.jsonl` (one `HOLDOUT_READ` line per candidate, dataset `CN_A_HOLDOUT` / R2 `CN_A_HOLDOUT_R2`).
- Decide "was it opened": `holdout_vault.jsonl` has a `HOLDOUT_OPEN_V1` row for the round. Decide "was it closed": the latest `MINING_ROUND_V1` row for the round has `status` in the terminal list. Read the ledgers tolerating a last line without a trailing newline (a container may be appending).

## 6. What a hard failure leaves behind

- **Refusal before the open** (everything in section 2): nothing is written except possibly access-log lines for panel reads (none before the open in the current code); no vault row, round status unchanged. The same command can be run again once the cause is fixed. **Deterministic refusals must not be retried in a loop**: they repeat byte for byte.
- **Crash after the open:** vault open row present, round `SCORING`, 0..N-1 gate records. Next step is `rescore` (section 4), once.
- **Field-state refusal** (`HOLDOUT_FIELD_EXCLUSIONS_V1`): a day on which one daily_basic field is MISSING for (nearly) every stock gives exit 2, before the open, stderr
  `{"error":"MINE_RUNNER_HOLDOUT_FIELD_INCOMPLETE","message":"MINE_RUNNER_HOLDOUT_FIELD_INCOMPLETE:market_daily_basic_observation_stock.csv:<field>:<YYYY-MM-DD>:<names>"}`
  (siblings: `..._HOLDOUT_FIELD_EMPTY:<file>:<field>` = no usable value on any sealed day; `..._HOLDOUT_FIELD_VALUES_INVALID` = a values cell is not JSON; a PRESENT state with a null value counts as MISSING). Going ahead needs a coordinator ruling page plus a `HOLDOUT_FIELD_EXCLUSIONS_V1` file `{schema:"HOLDOUT_FIELD_EXCLUSIONS_V1", round_id, ruling:{path,sha256}, exclusions:[{trade_date, field, reason}]}` passed as `<exclusions.json> <sha256>`; `total_mv` cannot be excluded. Without a ruling the refusal stands (draft S15 "要 Owner" is right). A timer must classify this code as a stop, alert once, and not retry.
